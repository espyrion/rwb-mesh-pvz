# Сценарий видео: демо-кокпит и «зелёная зона»

> Хронометраж — 2–2,5 минуты (требование Положения — 1–3 минуты). Все числа на экране приходят из API (`economics/params.yaml` →
> `/api/v1/economics/scenario` и другие эндпоинты). В кадре не называйте числа «прогнозом RWB»:
> это детерминированная модель. Если значение на экране отличается от этого текста — верьте экрану,
> текст описывает только порядок действий.

## Подготовка стенда (до записи)

```bash
# штатный стенд: UI :5173, API :8000 — этих портов и ждёт запись
docker compose up -d --build

# проверка, что стенд пригоден для записи (7/7 сценариев и health/deep)
.venv/bin/python scripts/demo.py

# запись видео по этому сценарию: Playwright, окно 1440×900, роль «Маркетплейс»,
# результат — docs/demo-backup.mp4 (длительность проверяется: 60–180 с)
.venv/bin/python scripts/record_demo.py
```

`scripts/record_demo.py` сам проходит кадры 1–3 (кабинет продавца → городской заказ → «Заказы»/«Собрать»/«Выдать»/«Начисления»,
«Экономика» с зелёной зоной и ползунком бонуса ПВЗ, «Демо-кокпит» шаг «отказ узла»), кодирует
видео через ffmpeg в H.264 1440×900 и падает, если длительность вне 60–180 с или разрешение не то.
Требует чистую БД (иначе шаг «отказ узла» покажет нули) и установленный Playwright:
`.venv/bin/pip install playwright && .venv/bin/python -m playwright install chromium`.
Адреса переопределяются: `WEB_URL`, `API_URL`, `OUT`.

Требования к кадру: светлая тема не нужна, шрифт браузера — 100%, окно 1440×900.
Роль API в левом нижнем углу: **Маркетплейс** (для скоринга и отказа узла), переключение на
**ПВЗ** показываем только в кабинете ПВЗ, если хотите подчеркнуть права.

## Кадр 1. Сквозной городской заказ (0:00–0:50)

1. **Кабинет продавца → Новый заказ**: оформить городской заказ. Показать маршрут: mesh 90 ₽ / 3 ч
   против хаба 135,50 ₽ / 30 ч.
2. **Заказы**: «Собрать» → «Выдать». В «Начисления» показать 4 стороны и сходимость ledger.

## Кадр 2. Экономика и зелёная зона (0:50–1:30)

1. Открыть **Экономика**: бейдж «зелёная зона: ДА/НЕТ» считается из ответа API
   (`/economics/scenario`), чек-лист: ΔПВЗ > 0, Δмаркетплейса ≥ 0, Δпродавца ≥ 0.
2. Дёрнуть ползунок «Бонус ПВЗ за заказ без хаба» — блок пересчитывается через API (задержка 350 мс).
3. Одной фразой: цепочка выигрывает на заказ, покупатель — в границах цены и срока.

## Кадр 3. Один сценарий из демо-кокпита (1:30–2:20)

Открыть **Демо-кокпит**, группа «5 обязательных сценариев ТЗ». Выбрать **один** шаг:

* **4. Ошибка в логистике / отказ узла** — «Выполнить шаг»: точка выводится из строя, остатки
  эвакуируются, заказы переадресуются, открыт инцидент; или
* **5. Длительное хранение** — часы идут вперёд до порога 21 день, приходит уведомление ПВЗ, партия
  перемещается на менее загруженную точку.

Показать PASS, строки «Лог различий» и счётчик прохождения. Реплика: «Каждый шаг — реальные запросы
к API, PASS/FAIL считается по полям ответа». Остальные сценарии (возврат, хаб, пик, восстановление) —
в кокпите по кнопке «Прогнать все 7 шагов»; в видео не показываем, чтобы уложиться в время.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| Шаг 1 FAIL, «overflow=true» | на стенде все точки уже загружены | пересоздать БД: `docker compose down -v && docker compose up -d --build` |
| Шаг 3 PASS с пометкой «уже была выведена» | точка была выключена до записи | это корректное поведение, шаг 4 вернёт её в строй |
| Скоринг вернул 403 | роль API — «ПВЗ» | переключить роль на «Маркетплейс» |
| «нет данных» вместо числа | API не отдал поле или запрос упал | не подставлять ноль: показать ошибку в кадре и пересчитать |

## Чего не говорить

* «Мы заменим логистику RWB» — в модели только расчёт, перевозок нет.
* «Экономия покупателя N рублей» без оговорки «в допущениях модели».
* «Зелёная зона всегда» — она зависит от параметров; ползунки это показывают.
